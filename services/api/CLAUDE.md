# services/api (Python, uv, FastAPI)

Turns restricted DXF floor plans into a canonical building model with provenance, then 3D GLB. Engine in `src/api/engine/`: adapters, canonical, geometry2d, geometry3d, exporters.

## Commands
- Postgres (repo root): `docker compose up -d`; schema: `uv run alembic upgrade head`; legacy import: `uv run api import-projects`
- Tests: `uv run pytest -q` (API tests need compose Postgres; they use a throwaway DB)
- Dev server: `uv run uvicorn api.main:app --reload`

## Accounts (`src/api/auth.py`)
- Every `/api/v1` router except `/api/v1/auth/*` depends on `current_user` (401 without a session). `/health` is public. Ownership is enforced through the single helper `api/access.py` (`owned`/`can_access`, `need` = viewer/editor/owner, default owner): no access, NULL-owner and soft-deleted rows all give 404. Sharing (`sharing.py`, owner only): grants by email, pending invites (claimed only on OAuth login with a verified email, never on password register), cap `MAX_COLLABORATORS`, one revocable `?share=<token>` read-only link; read-only endpoints use the `Principal` dependency. Projects keep immutable `project_versions`; `uv run api import-projects --owner <email>` assigns legacy projects.
- Edits: `PUT /jobs/projects/{pid}/floors/{fid}/edits` (editor+, job kind `edits`) stores the floor's ordered `edits` (`engine/edits.py`: ops carry a target snapshot, not an id) in the manifest, replays only that floor via `read_dxf(edits=)` and makes one version; `edit_target_missing` is a warning, a blocking result changes nothing; `_replay` keeps edits through parameter changes.
- Draft: job kind `draft` (`POST /jobs/uploads/{id}/draft`, upload owner) runs `read_project` per floor and stores nothing; result per floor = issues, stats, plan overlay (`plan_overlay.overlay_of`); accept = the normal generate/split calls.
- Jobs (`jobs.py`): `POST /api/v1/jobs/generations` and `/jobs/projects/{pid}/floors` return 202 `{job_id}`; one in-process worker thread runs them, `GET /jobs/{id}` is polled (stage queued/parsing/building-model/exporting/done, progress, error, result). Same access rules as the sync endpoints; `recover_jobs()` at startup fails jobs a dead process left running. Tests stub `jobs.submit` and call `jobs.execute`.
- Conventions (`engine/conventions.py`, `layer_conventions.py`): layer names are per-project config, not constants: preset (`aia` = the `Settings` defaults, `iso13567` minimal subset, `custom`) plus a layer->role mapping resolved into `Settings`. Saved per project (`project_conventions`, editor/owner write, viewer read); a floor request without `conventions` uses the project's. Unmapped layers stay `unmapped_layer` issues; `ignore` gives `layer_ignored_by_user`.
- Floors after generation (`projects.py`): `PATCH/DELETE /projects/{pid}/floors/{fid}` rename/remove (editor+, each a new version; geometry editing is Section D); `POST /projects/from-generation` turns a standalone model into a project. New floor ids are max index + 1.
- Building (`building.py`): `GET /projects/{pid}/building` (viewer) = floors by elevation with plan offsets, stair pairings, issues, stats; `PUT /floors/{fid}/offset`, `PUT /building/pairings` (confirm/re-pair), `POST /building/pairings/unpair` (editor+, each a version). Offsets and `pairings` live in the manifest (snapshotted); `auto` pairs are recomputed on read. Alignment and stair issues are warnings, nothing is auto-shifted.
- Materials: `PUT /projects/{pid}/materials` (editor+, new version) replaces the manifest map `"<floor id>/<element id>" -> library id` (ids = `MATERIAL_IDS`, must match `apps/web/public/materials/index.json`); returned by project and building GET; GLB meshes carry box-projected metre UVs (`exporters/glb.box_uv`).
- Lighting: `PUT /projects/{pid}/lighting` (editor+, new version, whole-setting replace, last write wins) saves `{location, north_deg, lights[]}` in the manifest (snapshotted, restored, a removed floor drops its lights); returned by project and building GET. At most 10 lights; quality is viewer-local and the sun follows the current local date and time.
- Exports (`exports.py`, `engine/exporters/{obj,ifc}.py`): `GET /projects/{pid}/export/{obj,ifc}` (all floors, plan offsets applied) and `GET /generations/{gid}/export/{obj,ifc}`, built on demand from stored canonical models, viewer role or share link. OBJ reuses `build_scene`. IFC4 in mm via IfcOpenShell (LGPL, library only): typed elements per storey, `VisualArc_Provenance` psets; no solid or no IFC type -> IfcBuildingElementProxy + issue (also in the `VisualArc_Export` pset).
- IFC import (`engine/adapters/ifc/reader.py`): an upload whose body starts `ISO-10303-21` is IFC (sniffed, not by name). `POST /uploads` returns `kind: ifc` + storeys as `floor_candidates`; `POST /uploads/{id}/ifc {project_name}` makes one project, a floor per storey (scope.handles = the storey GlobalId; `read_project` dispatches to `read_ifc`); `POST /generations` on it reads all storeys as one model. Geometry comes from IfcOpenShell tessellation in world coords (metres, x1000), sources are `SourceRef(format=ifc, layer=IFC class, entity_handle=GlobalId)` (rooms: `label_sources`). Mapped: IfcWall (bounding rectangle), IfcSlab, IfcDoor/IfcWindow (via IfcOpeningElement), IfcSpace, IfcStair (straight block stairs), IfcColumn, IfcRoof; everything else is an `ifc_unsupported_entity` issue. IFC floors cannot be edited (422); DXF parameters do not apply (values come from the file).
- DWG (`engine/adapters/dwg/convert.py`): an upload with an `AC10xx` header is converted to DXF in place by the ODA File Converter (not bundled; `ODA_CONVERTER_PATH` or the default install folders), run without a shell with `dwg_convert_timeout_s`; no converter, a failure or a timeout is a 422 with plain text (install instructions when absent). Tests fake the converter.
- PDF (`engine/adapters/pdf/`): a `%PDF-` upload is only inspected (`kind: pdf`, pages, colour/width groups, scale suggestions from a `1:N` note or agreeing dimension text; raster-only = 422 pointing to trace-assist); `POST /uploads/{id}/pdf {page, scale: ratio | two_points, confirmed: true}` is the only way to convert, and only with the user's confirmation (suggestions are never applied). It writes the page as a mm DXF over the upload (layers `PDF-<colour>-W<width>`, `PDF-TEXT`; original kept as `<upload>.pdf`, so another page or scale can be confirmed) and answers like a DXF upload; layer mapping follows. `read_project` refuses an unconfirmed PDF.
- Trace-assist (`underlays.py`): `POST /trace/floors?floor_name&(project_id|project_name)&elevation` (raw PNG/JPEG/PDF body, editor+) adds an EMPTY floor (source = `make_blank_dxf`, marked `$PROJECTNAME=visual_arc:blank-trace`, so `trace_floor_empty` is a warning instead of `no_plan_geometry`/`no_walls`) with the picture as `floor.underlay` (manifest, snapshotted). Images are checked by content, byte/pixel capped (Pillow bomb guard), re-encoded as PNG (a PDF renders page 1); nothing is detected or vectorised. `PUT .../floors/{fid}/underlay/calibration` stores the user's two pixel points + real distance (`user_provided`, mm per pixel); `GET .../underlay` serves the PNG (viewer/share link); the plan overlay carries `underlay`. Walls/doors/windows are then traced with the normal edit ops (`user_modified`). Pixel (px, py) = plan (px*m, (height_px - py)*m).
- Env: `ODA_CONVERTER_PATH`, `GITHUB_CLIENT_ID/SECRET`, `GOOGLE_CLIENT_ID/SECRET` (provider off = 503), `WEB_BASE_URL`, `AUTH_COOKIE_SECURE`, `SESSION_SECRET`, `AUTH_RATE_LIMIT_PER_MIN`.
- Tests: `conftest.py` logs in every `TestClient` automatically; mark auth tests `@pytest.mark.anon`.
